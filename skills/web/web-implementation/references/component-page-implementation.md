# Component & Page Implementation

## 组件职责

每个组件一事：视觉/交互边界清晰；页面编排组件组合规格区块，不把业务后端塞进展示组件（除非项目已有模式）。

## 组件状态（按需）

Default、Hover、Focus、Active、Disabled、Loading、Error、Success、Expanded、Collapsed。  
仅实现规格与可达性所需状态；有样式无行为 ≠ 交互已实现。

## 复用

跨页 Header/Footer/Nav/Button/Card/Form Controls 优先提升共享。多页时先抽共享再写专属。

## 边界反模式

- 一组件承担全站所有页。  
- 为每个边距建无意义组件。  
- 巨型 props 开关控制一切页面差异。  
- 文案、样式、异步逻辑缠死难测。

## 组件验收

用途、输入、状态、视觉规范引用、响应式行为、必要交互测试（或标 NOT TESTED）。

## 页面实施计划（每页）

- 页面目标、模块与顺序、模块关系  
- 使用组件、关键内容、主操作  
- 响应式行为、素材需求  

### 内容诚实

禁止虚构：案例、评价、商业数据、资质、合作品牌、用户数、转化率、价格（除非用户提供并标 FACT）。  
缺内容：明确 PLACEHOLDER，列入 Pending。

### 素材

优先用户资源目录；不引入版权不明商用图；随机图填满 ≠ 设计完成。

### 多页

识别共享壳、专属块、导航、差异；避免复制粘贴三份 Header。
