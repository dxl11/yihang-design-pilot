# web-page-design · 方法论

## 普通做法 vs 专业做法

| 普通 AI | 资深做法 |
|---|---|
| 一页套用英雄区 + 三列功能卡 + Logo 墙 | 先定页面任务与决策路径，再选模块 |
| 所有页面同一信息顺序 | 按页面类型调整比较、信任、转化节奏 |
| 只列区块名称 | 解释为何此序、首屏必须出现什么 |
| 按钮无去向 | 写触发、响应、成功/失败状态 |
| 编造「10 万学员」「98% 好评」 | 无来源则 TODO 或标注占位 |
| 另起一套流行色 | 继承 Design Tokens 语义色 |

## 推荐方法（按需选用）

1. **页面 Jobs / 任务分析**：用户「雇」本页完成什么活？  
2. **决策阶段匹配**：认知 → 考虑 → 比较 → 行动；模块对齐阶段。  
3. **信息优先级矩阵**：影响转化 / 影响理解 / 仅装饰 → 砍装饰。  
4. **F 型 / 分层扫描**：首屏主张与主 CTA 落在高注意区（启发式，非眼动伪造）。  
5. **信任缺口分析**：缺什么证据用户不敢行动？仅补**真实可获得**的信任模块。  
6. **内容密度控制**：教育营销站忌首屏堆指标；可读性优先。  
7. **设计系统约束设计**：组件变体从系统选；页面只做组合与例外说明。

## 何时停 vs 带着假设继续

- **停**：无页面标识；无任何转化目标且用户拒绝假设。  
- **继续**：缺价格数字、评价原文、素材授权——标 TODO，改用咨询 CTA 或条件模块。

## 不可伪造

用户访谈结论、量化漏斗、客户评价原文、未确认价格、认证徽章、竞品「我们测过转化更高」。
