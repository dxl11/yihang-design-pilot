# 视口策略与断点

## 视口带（设计关注）≠ 设备商标

| 视口带 | 典型测试宽度（建议） | 关注点 |
|---|---|---|
| Narrow Mobile | 320–374 | 溢出、字号、单列 CTA |
| Mobile | 375–639 | 主任务路径、汉堡导航 |
| Tablet | 640–1023 | 双列尝试、导航过渡 |
| Desktop | 1024–1279 | 完整 Primary Nav、多栏 |
| Wide Desktop | ≥1280 | 容器封顶、勿无限拉字 |

测试宽度用于走查；**实现断点**优先继承项目 `design-tokens.json` 的 `breakpoint.sm|md|lg|xl`（本仓库启航案例：640 / 768 / 1024 / 1280）。

## 断点理由模板（输出中必填）

对每个采用的 token 断点写：

1. **触发冲突**：何种布局/组件在该宽度失败？  
2. **变化**：导航、栅格、模块顺序、交互各变什么？  
3. **不变**：哪些必须跨屏保持（主转化、品牌名、关键决策信息）？

若某 token 断点对本页无行为变化，可声明「本页不额外挂钩」，避免假断点堆砌。
