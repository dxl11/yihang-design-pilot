# web-responsive-design · 方法论

## 普通做法 vs 专业做法

| 普通 AI | 资深做法 |
|---|---|
| 手机 = 单栏，完事 | 找出溢出、触达、决策信息被挤掉的冲突再定断点 |
| 断点抄 768/1024 | 断点对齐内容换行与组件折行点；解释为何 |
| 移动端狂藏模块 | 隐藏须有任务理由；决策信息改为折叠或换序 |
| Hover 说明书 | 触控等价路径；focus-visible 保留 |
| 另起一套手机色板 | 继承语义 tokens；仅调字号/间距阶梯 |
| 「已适配完成」 | 无跑测则 NOT TESTED |

## 推荐方法

1. **冲突驱动断点**：先列风险，再映射 `breakpoint.*`。  
2. **任务保持**：窄屏仍能完成主转化（申请/咨询）。  
3. **渐进增强布局**：桌面增强，移动不残缺。  
4. **比较型 UI 转换**：表 → 卡；并排 → 栈；保留维度。  
5. **触控目标**：主操作 ≥ 44×44 CSS px（目标，待测）。  
6. **验证分层**：设计自检 / 可脚本化 / 真机浏览器。

## 不可伪造

浏览器截图结论、axe/Lighthouse 全绿、真实用户手机测试通过率。
