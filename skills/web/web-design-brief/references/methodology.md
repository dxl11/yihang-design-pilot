# web-design-brief · 方法论

## 普通做法 vs 专业做法

| 普通 AI | 资深做法 |
|---|---|
| 把用户一句话扩写成空泛「提升品牌形象」 | 追问/推断可观察结果，或标模糊 |
| 直接写 3 个 Persona 故事 | 无证据则只写任务假设 |
| 把竞品首页风格当需求 | 分析信息组织与转化策略 |
| 默认全站大而全 | 强制「不做清单」 |

## 推荐方法（按需选用）

1. **目标分层**：Business → User → Site；冲突表。  
2. **任务分析 / JTBD 轻量版**：用户雇网站完成什么「活」？  
3. **利益相关者扫描**：谁拍板、谁供内容、谁受法务约束。  
4. **MoSCoW**：must / should / could / won't。  
5. **假设日志**：每条假设写「若为假，设计何处失效」。  
6. **成功指标草案**：输出、行为、体验代理指标；无基线则 TODO。

## 何时追问 vs 继续

- 追问：连品类/主转化都不清。  
- 继续：品类与主转化清楚，但缺竞品名单、精确画像等。

## 不可伪造

用户原话、定量数据、竞品「实测结论」（无浏览/无材料时）。
