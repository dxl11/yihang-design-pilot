# yihang-design-pilot 产品需求

> 开源本地 AI Design Agent 工具。非 SaaS。日期：2026-11-03。

---

## 1. 产品定位

**一句话**：让不同 AI Agent 通过同一套本地设计能力引擎，在品牌约束下完成可验收的 Web / PPT（及后续品类）专业设计交付。

**不是**：在线设计平台、自动美工网站、Claude Design 竞品云服务、企业设计中台。

---

## 2. 目标用户

| 用户 | 诉求 |
|---|---|
| 独立开发者 / 创始人 | 用 Cursor 等快速产出官网、路演 PPT，且跟得上自己的品牌 |
| 设计师 + AI 工作流 | 要可控方向探索与可编辑交付物，而非随机生图 |
| 开源贡献者 | 能读懂引擎、加规则/导出器/适配器 |
| 代理商/工作室（本地） | 可审计的品牌资产与版本，数据不出本地 |

非目标用户：需要采购「云端席位订阅」的纯业务采购方（本项目不提供该产品形态）。

---

## 3. 使用场景（Phase 1）

1. **品牌建档**：从 logo/官网/PDF 规范建立 BrandProfile，供后续任务引用。  
2. **品牌官网 / 落地页**：三方向探索 → 选定 → HTML 交付 → 截图质检 → 打包。  
3. **路演 / 汇报 PPT**：HTML Deck → PDF；需要时导出可编辑 PPTX。  
4. **跨 Agent 复用**：同一项目目录在 Cursor 与 Claude Code 间切换，任务状态仍在 `.ydp/`。

---

## 4. 功能范围

### 4.1 必须有（MVP）

- 本地安装与 `ydp doctor`  
- DesignTask 创建与状态流转  
- DesignBrief 结构化  
- 三方向提案 + 审批门禁  
- BrandProfile 最小集（资产路径 + 色板 + 字体）  
- Web：交付目录规范 + verify + lint  
- PPT：HTML deck 模板 + PDF 导出 + PPTX 双模式之一可用  
- QualityReport JSON  
- Cursor / Claude Code / Codex 适配文档与最小 Skill/规则包  
- MIT 许可与基础开源文档  

### 4.2 应该有（MVP 后）

- Brand 版本对比  
- 风格 Knowledge Pack 导入  
- ledger 级「避免重复外观」  
- PPTX 双模式均稳定  
- Windows 一等公民脚本  

### 4.3 可以有（后续）

- 海报 / 社交媒体 / 电商视觉模块  
- Motion / 视频包装  
- 可选云插件（TTS、视觉评审）  
- SQLite 索引  

### 4.4 明确不做

- SaaS 账户、多租户、订阅支付、商业运营后台  
- 云端项目托管为默认路径  
- 「无人类审批的全自动品牌总监」承诺  
- 绑定单一模型厂商

## 5. 阶段目标

| 阶段 | 目标 | 成功标准 |
|---|---|---|
| P0 审计规划 | 本轮文档 | 用户审阅通过 |
| P1 骨架 | CLI + Core FSM + Store + doctor | 无 Agent 也能跑通假任务状态 |
| P2 质检导出 | Quality + Export 迁移验证 | fixtures VERIFIED |
| P3 设计闭环 | Brief→Direction→Web/PPT 样例项目 | 人工+CLI 完成一条链路 |
| P4 适配器 | 三宿主可调用同一 CLI | 文档可复制安装 |
| P5 开源发布 | v0.1 标签 | CI 绿、许可证清单完整 |

## 6. 体验原则（产品层）

- **先看见再选择**：方向必须有真实视觉稿/截图，不只文字形容词。  
- **门禁文件/状态可见**：用户能指出卡在哪一状态。  
- **红灯不可假装完成**：Quality 失败不得标 COMPLETED。  
- **品牌优先于风格轮盘**：有 BrandProfile 时，方向探索在品牌约束内分化。  
- **本地可删可搬**：卸载即删项目目录与可选全局配置。  

---

## 7. 与 Huashu Design 的产品差异

| 维度 | Huashu | yihang-design-pilot |
|---|---|---|
| 交付形态 | Skill 为主 | 引擎 + Adapter |
| 品牌 | 强协议文档 | 结构化 Brand Engine（目标） |
| 质检 | 优秀脚本 | 一等公民模块 + 报告 schema |
| 扩展 | 兄弟 skill 生态 | 协议化模块/插件边界 |
| 品牌归属 | 花叔作品 | 独立开源项目品牌 |

借鉴其设计纪律（三方向、资产>色值、事实型 lint），但产品身份独立。

---

## 8. 验收视角（用户故事摘要）

1. 作为开发者，我在 Windows 上按文档安装后，`ydp doctor` 告诉我缺什么。  
2. 作为用户，我用 Agent 说「做官网」，系统先要我批方向，而不是直接出最终稿。  
3. 作为用户，我提供 logo 后，后续页面主色来自 BrandProfile 而非随机。  
4. 作为用户，我导出的 PPTX 能在 PowerPoint 里改字（在所选模式下）。  
5. 作为贡献者，我能加一条 quality rule 而不改 Adapter。

## 9. 补充：Web Design Skills 产品要求（P2.0 · 叠加，不覆盖上文历史）

> 依据 D-001 Skills-first 与 Prompt 2.0。上文 §1–§8 保留 Prompt 0 引擎视角作为历史需求；**当前实施以 Skills 为准**。

### 9.1 必须有（已交付）

- 独立 Skill：Brief、IA、视觉方向、设计系统、页面设计、响应式、设计审查、网页实现、**视觉验证**。  
- 结构化交付：`01`–`03`、`04`–`08` 目录 + tokens。  
- 事实/假设标记；禁止伪造用户研究与未执行的工具/浏览器/审查/实现/视觉通过结果。  
- 工作流编排与状态诚实标注；实现遵守项目发现与代码保护；验证遵守工具模式与视口追溯。  
- 贯穿案例（含实施与视觉验证 CASE_DEMO）+ `pnpm verify`。

### 9.2 必须有（后续，未交付）

- 真实用户前端工程上的端到端运行与多宿主浏览器实测证据（超出本仓 CASE_DEMO）。  
- 可选：在用户项目内启用 Playwright 的 MODE A 实跑样例（非本仓强制依赖）。

### 9.3 明确不做（持续）

- Agent Runtime / 多 Agent 调度平台 / SaaS / 账户计费。  
- 把未实现 Skill 标为 available 或建空壳目录。
